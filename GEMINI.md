# tikkit

Ticket-creation toolkit. Multiple skills (`/tik`, `/figtik`, `/stitchtik`, `/foundationtik`, `/modernizer`) take different inputs and converge on one shared backlog. Each skill's frontmatter has its own trigger phrases — Gemini will route to them automatically.

## Shared backlog convention

All tikkit skills (and repokit, if installed) write to the same place in the consuming project:

- `.backlog/backlog.md` — master checklist, one line per item, tagged by source
- `.backlog/tickets/<slug>.md` or `.backlog/tickets/<slug>/ticket.md` — full ticket

**Always read `.backlog/backlog.md` before creating a ticket** to avoid duplicates.

Position in `backlog.md` IS the priority/dependency order. Slugs are plain kebab-case, no numeric prefixes.

## Tag ownership

| Tag | Owner |
|-----|-------|
| `[tik]`, `[figtik]`, `[stitchtik]`, `[foundationtik]`, `[modernizer]` | tikkit |
| `[feedback-loop]` | repokit |

Use the tag matching the skill that produced the ticket. Don't invent new tags.

## `foundationtik` ↔ repokit

`foundationtik` reads `FOUNDATIONS.md` (generated by repokit's `dockit`) and never edits it. If the registry is missing, halt and recommend `/repokit:dockit`. If drift is detected, file a `foundation-stale-review` ticket recommending `/repokit:dockit sync` rather than editing the registry directly.
